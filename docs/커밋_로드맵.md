# journal-entry-risk-detector · 단계별 커밋 로드맵

> 목표: **의미 있는 커밋을 꾸준히** 쌓아서, 감사 실무(전표 테스트, ISA 240)를
> 데이터로 자동화한 과정을 그대로 보여준다.
> 억지 커밋(빈 커밋)은 금물 — 각 단계가 "진짜 한 걸음"이 되도록 쪼갠다.

---

## 지금 위치

`가상 전표 생성` 단계. 아래 **STEP 2**에 해당한다.
`src/generate_sample_data.py` 로 정상 전표 200장 + 이상 전표 32장(7가지 유형)이
섞인 `data/sample_journal_entries.csv` 를 만들었다.

이 데이터에는 학습·검증용으로 `is_anomaly`, `anomaly_type` 정답 컬럼이 들어 있다.
탐지기는 이 두 컬럼을 **보지 않고** 스스로 이상 전표를 찾아야 하고,
마지막에 정답과 비교해 "몇 개나 맞혔는지" 채점하면 된다.

## 전체 로드맵 (각 STEP = 1개 이상의 커밋)

### STEP 1 · 프로젝트 뼈대  ✅ (이미 완료)
- README, requirements.txt, .gitignore, src/·docs/ 폴더
- 커밋 예: `docs: 프로젝트 목표와 탐지 대상 위험요소 정리`

### STEP 2 · 가상 전표 생성  ⬅️ (지금)
- `src/generate_sample_data.py` 추가
- `data/sample_journal_entries.csv` 생성
- 커밋 예:
  - `feat: 가상 전표 생성기 추가 (정상/이상 전표 혼합)`
  - `data: 검증용 샘플 전표 CSV 생성`
  - `docs: 심어 둔 이상 전표 7가지 유형 설명 추가`

### STEP 3 · 데이터 불러오기 + 기초 점검
- CSV를 pandas로 읽는 `src/loader.py`
- 차변합 = 대변합 확인, 결측치·컬럼 점검
- 커밋 예: `feat: 전표 데이터 로더와 차대변 균형 검증 추가`

### STEP 4 · 이상탐지 규칙을 '하나씩' 모듈로
> 여기가 커밋을 가장 많이 쌓을 수 있는 구간이다. **규칙 1개 = 커밋 1개.**
- `feat: 고액 전표 탐지 규칙 추가`
- `feat: 적요 누락 탐지 규칙 추가`
- `feat: 중복 전표 탐지 규칙 추가`
- `feat: 비정상 입력시간(주말·심야) 탐지 규칙 추가`
- `feat: 직무분리 위반(입력자=승인자) 탐지 규칙 추가`
- `feat: 승인 한도 직전 금액 탐지 규칙 추가`
- `feat: 라운드 금액 탐지 규칙 추가`
- (여유되면) `feat: 벤포드 법칙 기반 첫자리 분포 이상탐지 추가`

### STEP 5 · 규칙을 모아 '위험 점수' 만들기
- 각 전표가 걸린 규칙 수/가중치로 위험 점수 산출
- 커밋 예: `feat: 규칙별 가중치를 합산한 전표 위험 점수 로직 추가`

### STEP 6 · 결과 리포트
- 위험 전표 목록을 CSV 또는 HTML 리포트로 출력
- 커밋 예: `feat: 위험 전표 리포트(HTML) 생성 기능 추가`

### STEP 7 · 정답과 비교해 '채점'
- `is_anomaly` 정답과 비교해 정탐/오탐/미탐 집계 (precision/recall)
- 커밋 예: `test: 탐지 결과를 정답 라벨과 비교하는 평가 스크립트 추가`

### STEP 8 · 테스트 코드
- 각 규칙이 의도대로 동작하는지 pytest로 검증
- 커밋 예: `test: 이상탐지 규칙별 단위테스트 추가`
- ※ 감사인의 '검증 마인드'가 드러나는 부분이라 특히 인상이 좋다.

### STEP 9 · 마무리 문서화
- README에 사용법·결과 예시·감사 실무와의 연결 정리
- 커밋 예: `docs: 사용법과 감사 실무(전표테스트) 연계 설명 보강`

## 초보자용 git 사용법 (이번 STEP 2 올리는 법)

터미널에서 프로젝트 폴더로 이동한 뒤:

```bash
# 1) 현재 상태 확인
git status

# 2) 이번에 추가/수정한 파일을 '무대에 올리기'
git add src/generate_sample_data.py data/sample_journal_entries.csv

# 3) 커밋 (한 걸음마다 메시지를 남긴다)
git commit -m "feat: 가상 전표 생성기 추가 (정상/이상 전표 혼합)"

# 4) 깃허브로 올리기
git push
```

### 좋은 커밋 습관
- **작게, 자주.** 파일 하나·기능 하나 끝날 때마다 커밋한다.
- **메시지는 "무엇을 왜".** `feat:`(기능) `fix:`(버그) `docs:`(문서)
  `test:`(테스트) `data:`(데이터) 처럼 앞머리를 붙이면 히스토리가 깔끔하다.
- **빈 커밋·의미 없는 커밋은 넣지 않는다.** 오히려 마이너스다.
- 하루에 몰아서 30개 push 하기보다, **며칠에 걸쳐 꾸준히** 올리는 흐름이
  "진짜로 공부하며 만들었다"는 인상을 준다.
